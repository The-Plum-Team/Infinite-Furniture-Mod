## What Infinite Furniture is

Infinite Furniture is an Architectury mod for Minecraft 1.20.1 on Fabric and Forge. Its one piece
so far is the wardrobe. It depends on Architectury API alone: the furniture is drawn by its own
`FurnitureModel`, so it needs no rendering library. `gradle.properties` is the single inventory of
the Minecraft version, loaders and dependency versions; never repeat it in a workflow, script or
document.

A wardrobe is a rectangle of wardrobe blocks, one or two wide along `WardrobeStructure.side()` and
one or two high, all with the same facing; each block's `part` is its column plus twice its row,
and the anchor (part 0) holds the contents and draws the model. `WardrobeStructure.plan` is the
only place that decides what a click with a piece builds: the client's ghost preview and the
server's merge both call it, so they cannot disagree. It takes the largest rectangle (2x2 first)
that contains the clicked wardrobe and the new block and whose other cells are whole wardrobes of
the same facing; fronts and backs never join. Breaking any block dismantles the whole wardrobe,
dropping its contents and one piece per block (none for a creative break).

The models are Blockbench files in `art/wardrobe/` (generated by `art/wardrobe/generator/`).
`tools/convert_models.py` is the only writer of the files it lists under
`common/src/main/resources/assets/infinitefurniture` (`furniture/*.json` models with their
animations, textures and the item model); edit the `.bbmodel` and regenerate, never the outputs.
The models keep Blockbench's scene coordinates and keyframe values, which are Minecraft's block
axes in pixels: `FurnitureModel` moves a bone by its keyframe position and turns it by its keyframe
rotation (Z, Y, X order, about its pivot) as they are, so the game shows what Blockbench shows.
Only Blockbench's Bedrock export mirrors X; nothing here does.

The textures follow the art direction recorded with the models: hand-placed pixels over a short
warm-wood ramp, no procedural noise.

## Task routing

| Change scope | Start from | Expected destination |
|---|---|---|
| Behaviour shared by both loaders | `main` | `common/src/main` |
| One loader's wiring (entry points, render hooks) | `main` | `fabric/` or `forge/` |
| Model, texture or animation | `main` | `art/wardrobe/*.bbmodel`, then `tools/convert_models.py` |
| Supported version/loader inventory | `gradle.properties` | The same file, with both loaders building |
| Generated output or staged artifacts | Nowhere | Fix the tracked input instead |

## Verification

```bash
git diff --check
python3 scripts/ci/mod_base_kit.py verify --network
python3 scripts/ci/mod_base_kit.py run template check --repo .
python3 tools/convert_models.py --check
./gradlew build
```

A change that touches what players see also runs `./gradlew :fabric:runShowcase` and
`./gradlew :forge:runShowcase` (under `xvfb-run -a` without a display). Each builds every wardrobe
with the real planning and merge code, checks contents, drops and the menu, writes
`run/showcase/screenshots/showcase-report.txt` (it must end in `ALL PASSED`) and photographs the
wardrobes closed, open, from behind and with the ghost; look at the screenshots.
